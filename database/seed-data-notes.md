# Seed Data Notes — E-Commerce Medallion Pipeline

Documentation of the three synthetic CSV datasets used as pipeline source files, generated by `src/data_generation/generate_sample_data.py`.

---

## 1. Overview

| File | Base Rows | Post-Injection Rows | File Size | Location |
|---|---|---|---|---|
| `customers.csv` | 10,000 | **10,011** | ~781 KB | `data/customers.csv` |
| `orders.csv` | 50,000 | **50,000** | ~3.0 MB | `data/orders.csv` |
| `products.csv` | 1,000 | **1,016** | ~64 KB | `data/products.csv` |

**Databricks deployment path:** `dbfs:/Volumes/workspace/default/medallion_data/`

> **Note on participant guide targets:** The assessment guide references ~10K customers, ~100K orders, and ~500 products as illustrative production-scale targets. This implementation uses **50,000 orders** and **1,000 products** (with post-injection row inflation from duplicate appends) to balance realistic volume with CE serverless execution time while preserving the full **700-defect** DQ manifest.

## 5. Production Volume Simulation

### 5.1 Why Synthetic Data at Scale

| Goal | How Seed Data Addresses It |
|---|---|
| **Volume testing** | 50K orders exercise Spark partitioning and aggregation without CE timeout |
| **Join cardinality** | Orders reference 10K customers × 1K products—realistic FK fan-out |
| **DQ at scale** | 700 defects across 50K rows ≈ 1.4% defect rate—typical of messy upstream exports |
| **Reproducibility** | `RANDOM_SEED = 42` ensures identical datasets across runs and environments |

### 5.2 Anomaly Rate Analysis

| Table | Injected Defects | Total Rows | Defect Rate |
|---|---|---|---|
| customers | 120 | 10,011 | ~1.2% |
| products | 125 | 1,016 | ~12.3% |
| orders | 455 | 50,000 | ~0.9% |
| **Total** | **700** | **61,027** | ~1.1% overall |

Order-level defects are the primary silver DQ validation target. Customer and product defects exist for future silver dimension tables and FK orphan testing.

### 5.3 Orphan FK Design

Invalid FK values are generated in ranges **above** the max valid ID:

- Invalid customer IDs: `max(customer_id) + 10,000` range (50 distinct values)
- Invalid product IDs: `max(product_id) + 10,000` range (30 distinct values)

This guarantees orphans cannot accidentally match valid parent keys.

## 6. Regeneration

```bash
# From repository root
python src/data_generation/generate_sample_data.py
```

Output includes row counts and the full `ISSUE_MANIFEST` table printed to stdout.

Upload to Databricks:

```bash
databricks fs cp data/customers.csv \
  dbfs:/Volumes/workspace/default/medallion_data/customers.csv --profile community --overwrite
# Repeat for orders.csv and products.csv
```

## 7. Data Freshness & Idempotency

- Regenerating with the same seed produces **byte-identical** CSVs.
- Bronze overwrite ingest replaces Delta tables completely.
- Silver/gold re-derive from bronze on each pipeline run.
- No incremental CDC in current phase—full refresh model.
